# Interview code guide

A plain-language review of the project's functions, stored variables, and important algorithm locals. Trivial loop counters and formatting temporaries are grouped rather than listed individually. Names ending in `_` are private members by convention, not special C++ syntax.

## 1. The 30-second explanation

> I built an embedded-style C++ controller that brings up a simulated SERDES receiver through a register interface. It waits for clock readiness, sweeps front-end equalization, trains feedback equalization, and verifies a BER target. The simulator processes symbols; firmware only reads measurements and adjusts registers. Tests cover repeatability, saturation, timeouts, training failure, and persistent degradation. Python checks learned taps against analytical expectations.

This is a **host-side behavioral prototype**, not deployed silicon firmware or proof of physical link performance.

### Vocabulary

| Term | Plain meaning |
|---|---|
| SERDES / PHY | Serial transmitter/receiver system / its physical-layer implementation. |
| NRZ symbol | One bit represented here by amplitude `-1` or `+1`. |
| ISI | Inter-symbol interference: earlier symbols leave contributions in the current sample. |
| PLL | Clock-lock mechanism; modeled here only as a delayed readiness flag. |
| CTLE | Front-end equalization; this model subtracts a scaled previous raw sample. |
| DFE tap | Weight used to subtract interference associated with an earlier symbol. |
| PRBS31 | Repeatable pseudorandom test-bit sequence generated by a 31-bit shift register. |
| BER / BERT | Bit-error rate / bit-error-rate testing with a known pattern. |
| Measurement window | A fixed number of symbols over which statistics are accumulated. |
| Q16 | Register representation with 16 fractional bits: multiply/divide by 65,536. |

### Ownership and data flow

```text
app/main.cpp
  FirmwareController  -> sequencing and pass/fail policy
    PhyDriver         -> typed operations and register encoding
      IRegisterIo     -> replaceable register-access contract
        SimulatedPhy  -> symbols, channel, equalization, counters

Python regression -> runs the executable -> checks JSON against reference taps
```

The application owns `model`, `phy`, and `firmware`. The driver and controller hold references to their dependencies; those dependencies must outlive them.

## 2. Shared types and measurements

Sources: [`phy_types.hpp`](../include/serdes/phy_types.hpp), [`statistics.cpp`](../src/statistics.cpp), [`channel_profiles.cpp`](../src/channel_profiles.cpp).

### `Measurement`

| Member / function | Meaning and purpose |
|---|---|
| `errors` | Number of incorrect receiver decisions in the window. |
| `symbols` | Number of tested symbols; denominator for BER and average correlations. One symbol carries one bit here. |
| `mean_squared_error` | Average squared difference between the known target and equalized sample; CTLE tie-breaker. |
| `mean_margin` | Average target-signed sample amplitude; positive means the sample is on the correct side of the decision threshold. Not a worst-case eye margin. |
| `error_correlations` | One accumulated sign-sign error correlation per tap; tells training which direction to adjust. |
| `valid` | Whether the measurement completed successfully with the requested nonzero symbol count. Check before using metrics. |
| `ber()` | Returns `errors / symbols`, or `1.0` if there are no symbols. Does not itself check `valid`. |
| `ber_upper_bound_95(measurement)` | Approximate one-sided 95% upper BER estimate; used for acceptance instead of observed BER alone. |

`ber_upper_bound_95()` returns `1.0` for no samples, uses `min(1, 3/N)` for zero errors, and otherwise uses a Wilson estimate. `count` is N, `observed` is measured BER, `kZ` is the one-sided 95% normal quantile, and `center`, `radius`, and `denominator` construct the Wilson upper endpoint.

**Interview point:** zero observed errors does not prove zero true BER. With 200,000 error-free symbols, the estimate is `1.5e-5`. The estimate is approximate; correlated DFE errors limit a simple binomial interpretation.

|---|---|

### Walk through `bring_up()`

1. Reset hardware and clear equalizer settings; wait for PLL lock.
2. Measure the unequalized baseline in verification mode.
3. Try CTLE codes 0–7 with DFE disabled and identical replayed data/noise. Choose fewer errors, breaking ties with lower MSE.
4. Keep the chosen CTLE and train DFE from zero. Each window supplies correlations for all three taps.
5. Stop after enough unchanged windows; fault if the window budget runs out.
6. Use a distinct deterministic sequence for decision-directed verification. Accept only if the BER upper estimate meets the target.

| Important local | Meaning |
|---|---|
| `report` | Evidence accumulated for this bring-up attempt; returned even on early failure. |
| `candidate`, `best_measurement`, `best_code` | Current CTLE trial and best result/settings seen so far. |
| `fewer_errors`, `equal_errors_lower_mse` | Explicit ranking rules. Code zero establishes the initial best candidate. |
| `measurement` | Current DFE training window's statistics. |
| `normalized_correlation` | Correlation sum divided by symbol count; average sign agreement, not a full Pearson correlation. |
| `old_code`, `new_code` | Existing tap setting and requested next setting, calculated as `int` to avoid narrow-integer arithmetic problems. |
| `taps_changed` | Whether any actual tap setting changed during this window's update. |
| `unchanged_windows` | Consecutive windows with no tap movement; reset whenever a tap changes. |
| `training_converged` | Records that the stability rule was met, rather than merely exhausting the loop. |
| `window`, `tap`, `elapsed` | Training-window index, tap index, and consumed PLL ticks. |
| `kBaselineSeedMask`, `kSweepSeedMask`, `kTrainingSeedMask`, `kVerificationSeedMask` | XOR masks producing repeatable stage-specific seeds. All CTLE candidates reuse the sweep seed for fair comparison. |

**Why read back a tap?** A request from 63 to 66 is clamped to 63, so requested movement is not actual movement. `taps_changed = taps_changed || (readback != old_code)` preserves any earlier change. Once true, `||` short-circuits and skips later readbacks in that expression.

**Why verify after convergence?** Unchanged taps can mean saturation, not good equalization. Stability alone does not establish acceptable BER.

### States, failures, and results

| Enum | Values and meaning |
|---|---|
| `LinkState` | `Idle`: not started; `Reset`: initializing; `WaitForPll`: clock wait; `CtleSweep`: front-end search; `DfeTraining`: feedback adaptation; `Verify`: acceptance test; `LinkUp`: accepted; `Degraded`: persistent poor BER; `Fault`: bring-up/hardware/measurement failure. |
| `FaultReason` | `None`, `PllTimeout`, `MeasurementFault`, `TrainingNotConverged`, `BerTargetMissed`: distinguish why bring-up returned. |
| `HealthAction` | `Healthy`: pass; `Observe`: bad BER but not enough consecutive failures; `RetrainRequired`: caller should recover; `NotLinkUp`: health test was not run. |

Lost PLL or invalid health measurements immediately cause `Fault` and a retrain request. BER failures use hysteresis: the first two default failing windows return `Observe`; the third changes state to `Degraded`. A healthy window clears the bad-window count.

|---|---|
| `success`, `fault` | Final outcome and explicit failure explanation. |
| `baseline`, `trained` | Before/after verification measurements. Early exits may leave later fields at defaults. |
| `selected_ctle_code`, `trained_dfe_taps` | Chosen front-end code and saved trained tap codes. |
| `training_windows` | Number of training windows attempted. |
| `state_trace` | Fixed-capacity record of bring-up transitions. |
| `state_trace_size` | Number of valid trace entries; unused array entries are not transitions. |
| `kMaxTraceStates` | Trace capacity of 16, avoiding dynamic growth. |

### `PhyDriver`

Its only stored variable, `io_`, is a reference to the selected register backend.

| Function | Plain explanation |
|---|---|
| `PhyDriver(io)` | Attach a backend without owning it. |
| `reset()` | Write reset asserted, then deasserted. |
| `tick()` | Forward one time step to the backend. |
| `is_pll_locked()` | Test the PLL-ready status bit. |
| `restart_test_sequence(seed)` | Mask the seed to 31 bits and write the seed register. |
| `set_ctle_code(code)` / `ctle_code()` | Clamp/write the CTLE setting / read its low byte. |
| `set_dfe_tap_code(index, code)` | Check index, clamp the signed code, encode its byte, and write it. Invalid indices are ignored. |
| `dfe_tap_code(index)` | Decode a signed tap byte; invalid indices return zero. |
| `clear_dfe_taps()` | Set all tap codes to zero. |
| `dfe_tap_codes()` | Read all three tap settings into an array. |
| `measure(symbols, mode)` | Start a measurement, poll completion, decode counters/metrics, and return a validity-tagged result. |
| `decode_signed_word(value)` | Preserve the register's bits while interpreting them as a signed 32-bit integer. |

In `measure()`, `command` combines start/mode bits, `status` holds the latest flags, `kCompletionTimeoutTicks` limits polling to 8 ticks, and `result` holds decoded data. Missing completion or a fault returns an invalid default result. A completed measurement is valid only if its count matches the nonzero request. `kQ16Scale` converts fixed-point metrics back to doubles.

**Interview point:** policy is separate from register formatting. A real backend could implement the same contract, but would still need device-specific ordering, timing, transport errors, and coherent result reads. The current simulator completes measurements synchronously inside the start-register write.

### Walk through `step_symbol()`

```text
target_symbol    = next PRBS amplitude (-1 or +1)
raw_sample       = weighted transmitted-symbol history + Gaussian noise
front_end_sample = raw_sample - CTLE coefficient * previous_raw_sample
equalized_sample = front_end_sample - sum(tap weight * feedback history)
decision         = +1 if equalized_sample >= 0, otherwise -1
analog_error     = target_symbol - equalized_sample
```

The simulator compares `decision` against `target_symbol` to count a bit error. DFE history gets the target in training mode and the decision in verification mode.

| Local / result | Meaning |
|---|---|
| `SymbolObservation::bit_error` | Whether this symbol was decoded incorrectly. |
| `squared_error` | `analog_error²`; accumulated into MSE. |
| `signed_margin` | `target_symbol * equalized_sample`; negative means a wrong-side sample. |
| `correlation_signs` | Per-tap `sign(analog_error) * feedback_history[tap]`. |
| `error_sign`, `history_sign` | Signed inputs to that correlation; errors within ±`1e-12` get sign zero. |
| `accumulated`, `observation`, `denominator` | Window totals, one-symbol result, and divisor used to average MSE/margin. Correlations remain sums. |
| `nonzero_seed` | Safe replay seed; all-zero PRBS state is replaced with the default. |
| `kWarmupSymbols` | 32 symbols processed but excluded from reported counts after restart. |
| `kCtleCoefficients` | Eight selectable strengths from 0.00 through 0.65. |
| `first_uniform`, `second_uniform`, `radius`, `angle` | Box–Muller inputs/intermediates; the first is bounded away from zero before `log`. |
| `value`, `random_bits` | Working PRNG state and multiplied output bits. |
| `kOutputMultiplier`, `kScaleToUnitInterval` | xorshift64* output multiplier and `1/2^53` scale for converting the top 53 bits to a double. |
| `scaled`, `signed_value`, `kQ16Scale` | Fixed-point encoding intermediates and the 65,536 scale factor. |

**Why the update sign?** DFE subtracts the tap contribution. With `error = target - equalized_sample`, increasing a tap increases error in the direction of its history symbol. Moving opposite the error/history correlation tends to reduce that error.

**Model limitation:** applying CTLE to a four-cursor channel produces a fifth effective cursor. Three DFE taps cannot cancel every possible residual contribution. CTLE also changes noise, so stronger equalization is not always better.

## 9. Tests: what evidence each function provides

Sources: [`serdes_tests.cpp`](../tests/serdes_tests.cpp), [`test_reference_model.py`](../python/tests/test_reference_model.py).

### C++ test helpers

- `TestSuite::check(condition, expression, line)` increments `checks_`, records `failures_`, and prints failed assertions. `finish()` prints totals and returns process status.
- `CHECK` captures expression text and source line for diagnostics.
- `NeverCompleteIo::read32()` reports PLL lock but never completion; `write32()` ignores requests; `tick()` increments `ticks`. This isolates timeout behavior from the simulator.
- `same_measurement(first, second)` compares all measurement fields exactly for replay checks.
- Test `main()` runs the scenarios and returns `suite.finish()`.

| Test function | What it demonstrates |
|---|---|
| `test_prbs31_signature` | First 64 bits match a known signature; zero seed falls back safely. `signature` packs those bits for comparison. |
| `test_register_encoding_and_clamping` | Negative taps survive encoding and out-of-range equalizer settings saturate. |
| `test_measurement_timeout` | A never-completing backend produces an invalid result after exactly eight ticks. |
| `test_sequence_replay` | Identical seeds reproduce all metrics across profiles/modes, including odd window lengths that exercise noise-cache reset. `first` and `repeated` are the compared snapshots. |
| `test_ber_upper_estimate` | Zero-error rule-of-three and nonzero-error upper estimates behave as expected. |
| `test_bringup` | Each built-in profile brings up successfully, does not worsen measured BER, and ends at `LinkUp`. |
| `test_pll_timeout` | Forced PLL non-lock yields `PllTimeout` and `Fault`. |
| `test_training_exhaustion` | An insufficient window budget gives `TrainingNotConverged`. |
| `test_degradation_hysteresis` | After a good bring-up, an injected worse channel yields two `Observe` responses then a retrain request and `Degraded`. |

Common test locals `model`, `phy`, `config`, `firmware`, and `report` build isolated scenarios. `degraded` is a deliberately worsened profile; `seeds` supplies replay edge cases.

| `test_ideal_dfe_has_three_codes` | Default reference output contains three taps. |

## 10. C++ keywords worth explaining

| Syntax | Why it appears here |
|---|---|
| `[[nodiscard]]` | Ask the compiler to warn if a useful result, such as a measurement or report, is ignored. |
| `noexcept` | Promise no exception escapes. An escaping exception terminates the program; this is not error recovery. |
| `explicit` | Prevent unintended implicit construction/conversion, e.g. an integer silently becoming a PRBS generator. |
| `const` | Prevent modification through that variable/reference; on a method, restrict modification of ordinary object members. Does not imply thread safety. |
| `constexpr` | Express compile-time constants such as tap limits and lookup tables. |
| `inline constexpr` | Allow header-defined constants to be shared across translation units without multiple-definition problems. |
| `enum class` | Keep state/register values strongly typed and scoped. |
| `virtual`, `override`, `final` | Define replaceable I/O behavior, check correct overrides, and prohibit further inheritance where intended. |
| `std::array` | Fixed-size storage for taps/history/trace, without dynamic resizing. |
| `std::optional` | Represent a profile lookup that may have no result. |
| `std::bit_cast` | Preserve bits when switching signed/unsigned register interpretations. |
| `static_cast` | Make numeric conversions explicit; cast before division to avoid integer truncation. |
| `volatile` | Not needed for the current software backend. A future MMIO backend may require volatile accesses/platform accessors; volatile alone does not provide atomicity, thread synchronization, or hardware barriers. |

## 11. Questions to rehearse

1. **Why separate controller, driver, and simulator?** Policy stays testable without depending on symbol processing or a specific register transport.
2. **Why CTLE before DFE?** A small eight-code sweep cheaply chooses a front-end starting point, then feedback taps adapt. This staged approach is not a joint global optimizer.
3. **Why MSE as a tie-breaker?** Short windows can give equal error counts even when analog error quality differs.
4. **Why deadband and multiple stable windows?** Avoid reacting to small fluctuations or one quiet window; balance convergence speed against stability.
5. **Why distinct training and verification feedback?** Known symbols help adaptation; receiver decisions expose error propagation during acceptance testing.
6. **Why bounded waits?** A failed device must produce a diagnosable result instead of hanging firmware forever.
7. **Why health hysteresis?** Avoid retraining on a transient BER failure; invalid measurements and lost clock readiness still require immediate recovery.
8. **What would production require?** Real register transport, physical timing, stronger configuration validation, asynchronous scheduling as needed, hardware error handling, and measured-channel validation.
9. **What does this not model?** Continuous-time analog behavior, CDR, jitter, crosstalk, PAM4, PVT variation, or protocol training.
10. **What testing would you add?** Explicit healthy-window counter-reset tests, health early-return cases, BER-target rejection, mismatched measurement counts, configuration boundaries, and actual recovery orchestration.
