# Simpler code and clearer names — 2026-09-08

The cleanup makes the existing control flow easier to read. It keeps the register interface, register encodings, simulated device, bounded waits, state transitions, receiver equations, and failure policy. It adds no new service layer or generic framework.

## Simplifications

- Noise starts directly from the nonzero seed. The extra seed shift/XOR and unreachable zero-state fallback are removed.
- The first receiver-setting candidate initializes the comparison. Maximum-integer and infinity sentinel values are no longer needed.
- A plain `if`/`else if` chooses the tap-adjustment size instead of a nested conditional expression.
- The existing register-name typo is corrected to `ErrorCorrelation2`.
- The generator's output multiplier remains part of the algorithm and has a descriptive name. The four stage seed masks also have names, so the reason for each seed is visible at its call site.

## Name mapping

| Previous name | Current name | Meaning |
|---|---|---|
| `restart_pattern()` | `restart_test_sequence()` | Restart generated data, noise, and channel history together |
| `wait_for_pll()` | `wait_for_pll_lock()` | Wait for the phase-locked loop readiness flag |
| `pll_locked()` | `is_pll_locked()` | Read the readiness flag |
| `run_offline_bert_health_check()` | `check_link_health()` | Run an offline bit-error test; it still does not monitor live traffic |
| `adaptation_step()` | `dfe_tap_step()` | Choose the adjustment for a decision-feedback equalizer tap |
| `uniform01()` | `next_uniform_sample()` | Generate the next sample in [0, 1) |
| `gaussian_noise()` | `next_gaussian_sample()` | Generate the next bell-shaped noise sample |
| `spare_gaussian_noise_` | `cached_noise_sample_` | Hold the second sample produced by the noise conversion |
| `degraded_window_count_` | `consecutive_bad_windows_` | Count failing measurement windows in a row |

Measurement calls state their intent:

```cpp
phy_.restart_test_sequence(seed ^ kBaselineSeedMask);
report.baseline = phy_.measure(config_.verify_symbols, MeasurementMode::Verification);
```

`MeasurementMode::Training` feeds known transmitted symbols back into the receiver. `MeasurementMode::Verification` uses the receiver's own decisions. These replace the previous `true` and `false` arguments without changing the register command.

The public C++ method names and measurement argument type changed; callers should use the mapping above. Command-line options, JSON field names, register offsets, and serialized state/fault names remain the same.
